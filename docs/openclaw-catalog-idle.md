# OpenClaw 2026.9.7 model catalog worker idle retirement

The installed catalog pool explicitly sets `idleTimeoutMs: 0`, retaining a native worker after completed discovery and disabling that pool's idle-on-critical-memory subscription. A live diagnostic sample showed about 212 MiB used heap in this worker. Published catalog results and agent/runtime bindings belong to other owners; this worker executes bounded reconstruction requests.

`scripts/patch_openclaw_catalog_idle.py` enables the existing native pool's 60-second idle timeout for this one pool. No new timer owner, process killer, heap cap, model/auth change, session reset, database edit, or API exposure is introduced. The native pool cancels idle timers when dispatching a new task, waits for native sections during retirement, releases temporary capture resources, and recreates workers on demand. Its existing five-minute warm window may delay later retirements after repeated recreation.

This is an opt-in vendor overlay, not an upstream OpenClaw fix. Apply only to the exact 2026.9.7 package/source hash accepted by the script. Default is dry-run. Backups and a hash manifest precede atomic replacement. Repeated apply and unknown versions fail closed. Use `--rollback` with the same artifact directory and reload Gateway to restore the original. The rollback validates live and backup hashes before writing. Package upgrades may replace the overlay and require fresh source review.

Validation: `python3 scripts/test_catalog_idle_patch.py`; on the server, `node scripts/test_catalog_worker_idle.mjs <installed-openclaw-root> <task-artifact-tmp-directory>`. The native-pool fixture proves active work survives idle/pressure collection, completed idle workers retire, temporary resources are released, and another task creates a fresh worker. Deployment additionally requires current empty Gateway lanes, preserved core configuration/state, controlled restart, health/readiness checks, real model execution, and live catalog worker retirement/recreation evidence. A restart's aggregate memory reduction must be reported separately from this worker's measured saving.
